## Revisión: error auxiliar y contexto

El mock incompleto permitió reproducir un defecto de la aplicación: después de persistir una decisión, el fallo del aviso se guardaba en `errorMessage` y ocultaba la cola. Se separa `notificationErrorMessage`, se conserva el resultado de revisión y se presenta un aviso visible con reintento. Una regresión verifica **un POST de decisión y dos GET de aviso**: el reintento no vuelve a enviar la decisión.

El aviso valida generación, pedido y fecha; se cancela al cambiar contexto o destruir la vista. Las respuestas tardías del POST tampoco publican resultados de otro contexto. Las decisiones se serializan; cambiar fecha libera el bloqueo previo y una respuesta antigua no libera el bloqueo de una decisión nueva. No cambian endpoints, contratos de revisión, backend ni SQL.

Cinco casos nuevos de componente elevan el total a **47/47 correctos**. Las contrapruebas sobre el componente anterior dieron cuatro fallos y un éxito: la protección de destrucción ya cubría uno de los escenarios. Otra contraprueba reprodujo el bloqueo de revisión retenido al cambiar fecha. Los cuatro casos E2E de revisión mantienen la cola visible y verifican el reintento auxiliar sin repetir el POST. [Seguimiento F04](../corrections/C1-F04.md).

## Reparto: selección por nombre accesible

Los labels actuales de los select son válidos y sus nombres accesibles son breves. En Playwright 1.60, `getByLabel(..., { exact: true })` lee también el texto de las opciones cuando el select está dentro del label. `getByRole('combobox', { name: texto, exact: true })` utiliza el nombre accesible y excluye ese texto de opciones.

Se sustituyen cinco selectores dentro de los mismos diálogos: los cuatro que fallaron y el repartidor de la vuelta, que el fallo anterior impedía alcanzar. Se conservan exactitud, cantidades, payloads, reservas, custodia, permisos, ausencia de desbordamiento y tiempos. No se modifica el producto ni ARIA para resolver esta diferencia de selección.

No se eleva el límite del test ni se oculta el desbordamiento. Después del ajuste, el documento mide **768 px** y el borde inferior del área principal **765.03125 px**. Las comprobaciones existentes se refuerzan con intersección completa (`ratio: 1`) de las acciones y las siete casillas del calendario.
