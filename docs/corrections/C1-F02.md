# C1 — F02: límite de intentos de acceso administrativo

Fecha: 3 de noviembre de 2026, Ciudad de México. Base: I23 `aa802e2`,
integrada con el corrector y cierre confirmado del despliegue. Esta corrección
no modifica cuentas, contraseñas, permisos, tokens, tablas ni migraciones.

## Problema y corrección

`POST /api/auth/admin/login` no tenía límite de solicitudes en la aplicación.
La protección existente de acceso por token de cliente no cubría ese endpoint.

Se añade una política específica mediante el middleware estándar de ASP.NET
Core, separada de los casos de uso de autenticación:

| Control | Predeterminado | Configuración |
| --- | --- | --- |
| Intentos por IP efectiva | 10 por ventana | `Authentication:AdminLoginRateLimit:PerIpPermitLimit` |
| Intentos administrativos totales | 100 por ventana y proceso | `Authentication:AdminLoginRateLimit:GlobalPermitLimit` |
| Ventana fija | 60 segundos | `Authentication:AdminLoginRateLimit:WindowSeconds` |
| Espera en cola | Ninguna | Rechazo inmediato |

Los valores se validan al iniciar: límites positivos y ventana de 1 a 3600
segundos. Una configuración inválida detiene el arranque; no desactiva
silenciosamente la protección. También pueden establecerse mediante variables
de entorno sustituyendo `:` por `__`.

Al exceder un límite se devuelve `429`, `Retry-After` en segundos y un mensaje
fijo en español. El evento `1801/AdminLoginRateLimited` no incluye usuario,
contraseña, token, cuerpo de petición o IP. Se conserva `Cache-Control: no-store`
de los endpoints de autenticación. Los errores de credenciales siguen siendo
`401` con el mensaje genérico existente.

No se guarda un bloqueo por usuario ni se invalida una sesión: el límite expira
automáticamente. El límite global sólo afecta al inicio de sesión administrativo,
no a la operación autenticada, salud o acceso de clientes. Cuenta todas las
solicitudes administrativas, incluidas las que luego exceden el límite por IP.

La clave por IP usa `Connection.RemoteIpAddress` después del procesamiento de
cabeceras; no lee `X-Forwarded-For` directamente. Se mantiene la confianza
existente exclusivamente en el Nginx local (`127.0.0.1`/`::1`) y un salto. Cambiar
el despliegue a otro proxy exige configurar y verificar su confianza explícita.

Antes de consultar cuentas o verificar hashes se rechazan nombres mayores a
120 caracteres y contraseñas mayores a 1024. El primero coincide con la columna
SQL; el segundo conserva el límite de contraseña anterior que ya admite el
cambio de contraseña propia. No se reduce el límite a las 128 posiciones de las
contraseñas nuevas ni se recorta la entrada para autenticar otra credencial.

## Evidencia y validación

La prueba dedicada `AdminLoginRateLimitTests` cubre:

- `429` y `Retry-After`, cuerpo genérico y `no-store`;
- recuperación de acceso válido después de la ventana, sin bloqueo permanente;
- cabecera falsificada desde origen no confiable, sin evasión por cambiarla;
- IP efectiva de cliente a través del proxy local y límite global entre IP;
- salud, token de cliente y separación de permisos preservados;
- tres configuraciones inválidas rechazadas al arrancar;
- entradas sobredimensionadas rechazadas antes del repositorio o hash;
- autenticación de credenciales válidas en los límites 120/1024.

Resultado: **9/9 correctas**, cero fallos y cero omisiones; compilación Release
correcta. Ejecución focalizada del 3 de noviembre de 2026:

```bash
dotnet test tests/Prodimt.Pedidos.Application.Tests/Prodimt.Pedidos.Application.Tests.csproj \
  -c Release --filter FullyQualifiedName~AdminLoginRateLimitTests
```

Son pruebas HTTP en TestServer con persistencia InMemory y datos ficticios;
se ejecutan los middlewares reales de autenticación, cabeceras reenviadas,
autorización y rate limiting. Las pruebas de proxy fijan el peer en un filtro
exclusivo del host de pruebas; no existe ese filtro en producción. La recuperación
espera 1.1 segundos sobre una ventana de prueba de un segundo. No constituyen
validación de Nginx real, SQL Server, navegador o despliegue.

Archivos principales: `AdminLoginRateLimiting.cs`, registro de la política en
`Program.cs`, defaults de `appsettings.json`, validación temprana de
`PilotAuthenticationService.cs` y `AdminLoginRateLimitTests.cs`.

## Límites y siguiente validación

Protección en memoria por proceso: reiniciar el servicio inicia otra ventana.
El despliegue actual es una instancia; múltiples réplicas necesitarían un límite
compartido o en el proxy. Una IP compartida por varios operadores comparte su
cupo; los valores son ajustables sin cambiar contratos ni datos. No se afirma
resistencia completa a ataques distribuidos ni aceptación en producción.

Referencia técnica: [middleware de limitación de ASP.NET Core 10](https://learn.microsoft.com/aspnet/core/performance/rate-limit?view=aspnetcore-10.0).
