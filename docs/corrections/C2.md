## Aislamiento y recuperación

El runner no acepta conexiones ni URLs del usuario y no lee `api.env`.
Excluye variables heredadas de aplicación. Crea un contenedor Docker propio
con nombre/label/hostname UUID, puerto SQL loopback efímero y almacenamiento
desechable; no monta datos o volúmenes ajenos. Antes de DDL verifica servidor,
registra cada `C2_UUID` durablemente, y comprueba propiedad al limpiar.

La cuenta administrativa sólo migra/prepara/inyecta el fallo/limpia. El proceso
API usa un login SQL propio con reader/writer y DENYs publicados de precios,
setup, producción, reparto y horarios; comprueba permisos efectivos. Esto no
endurece AuditLogs1111 en producción ni certifica F24.

`finally` detiene sólo grupos de procesos creados por el runner y elimina
únicamente su contenedor con identidad/label comprobadas. Se verifica ausencia.
Antes de crear el contenedor se persiste `gate.json` con recuperación pendiente;
un SIGKILL conserva ese registro. `--recover DIRECTORIO` rechaza un supervisor
todavía activo y verifica UUID/propiedad antes de retirar el contenedor. Recuperar
limpieza nunca convierte pruebas incompletas en aprobadas.
