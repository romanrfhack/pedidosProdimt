## Hallazgo y cambio

`npm test` en la aplicación apuntaba a `ng test`, aunque `angular.json` no
declaraba ese target. El typecheck de todos los specs Playwright tampoco tenía
configuración propia ni los tipos Node que necesita `Buffer`.

- `npm test` en `apps/prodimt-pedidos-web` ejecuta ahora las pruebas de
  comportamiento de `tests/component` en Node 24. El harness carga las clases
  TypeScript originales y el inyector/compilador reales de Angular, usando las
  dependencias del lockfile existente. Cada caso proporciona explícitamente los
  dobles de transporte, almacenamiento y detección de cambios que necesita.
- `tests/e2e/tsconfig.json` comprueba **todos** los specs TypeScript y sus fixtures
  con `strict` y `noEmit`. `@types/node` 24.19.2 y su dependencia de tipos quedan
  fijados en el lockfile E2E; no cambian Angular, Playwright ni dependencias runtime.
- Los selectores históricos de revisión en `customer-order.spec.ts` se alinean
  con los textos vigentes de I23: «Pedidos por confirmar» y «Ver detalle / ajustar».
  Esta corrección está tipada y colectada; no se declara ejecutada en navegador.
- CI añade ambos controles y conserva el build Angular y Playwright con API
  simulada. Los comandos y límites de cada nivel están en
  [tests/component/README.md](../../tests/component/README.md).

El harness sólo transpila para ejecutar; no sustituye el análisis de tipos ni
la compilación de plantillas. El build Angular sigue siendo obligatorio.
