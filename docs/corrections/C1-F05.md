# C1 · F05 — Conservar borradores de horarios

Fecha: 3 de noviembre de 2026, Ciudad de México. Base de aplicación: `aa802e210d15c70784f79dea2580709166b843c7`, I23 instalado según reporte del usuario. Hallazgo original: [F05](../audits/2026-11-03/AUDITORIA.md).

## Problema y corrección

Guardar la tarjeta A disparaba una lectura completa y sustituía el borrador B. Además, `saving` pasaba a `false` antes de recuperar las nuevas versiones del servidor. La interfaz podía volver a enviar una versión obsoleta en ese intervalo.

El componente conserva un snapshot del servidor separado de los campos editables y reconcilia las tarjetas por identidad. El guardado confirmado actualiza solamente la tarjeta enviada; un refresco mantiene los demás borradores. La búsqueda sigue activa y conserva su valor. Durante el PUT y el GET posterior permanecen bloqueados los inputs de horario y los guardados.

La actualización de versiones es explícita ante concurrencia: un 409 vuelve a consultar y conserva el borrador. Cuando la versión de una tarjeta editada cambia, se muestra el valor actual y se bloquea Guardar hasta elegir **Usar horario actual** o **Conservar mi cambio sobre la versión actual**. Esta segunda acción conserva la hora editada y adopta la versión que se acaba de mostrar; no envía automáticamente otro PUT. El servidor sigue aplicando `expectedVersion` y puede rechazar una nueva carrera.

Si falla el GET posterior al guardado, se conservan las tarjetas y se exige **Actualizar horarios** antes de permitir otro envío. Si un registro desaparece, su borrador queda visible y bloqueado hasta descartarlo expresamente. Las lecturas anteriores se cancelan y las suscripciones se cierran al destruir la vista. Borrar una excepción sigue enviando `cutoff: null`; la herencia se calcula con el horario de ruta guardado, no con su borrador.

## Alcance y compatibilidad

Sólo frontend. Se conservan URLs, DTOs, autorización, unidades de tiempo, reglas de herencia y concurrencia. No hay migración, cambios de backend, datos productivos ni despliegue. La corrección conserva borradores dentro de esta vista; no añade persistencia de borradores tras cerrar sesión o recargar el navegador.
